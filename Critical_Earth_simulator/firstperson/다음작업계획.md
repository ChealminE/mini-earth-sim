### 계획과 달라진 점

- **Stage B 지면 색** — 재질 색을 흰색/갈색으로 틴트해서 눈·단풍을 표현하려던 계획은 실패했다.
  재질 색은 텍스처에 **곱해지므로** 흰색은 항등원이라 아무 변화가 없고, 곱셈은 어둡게만 할 수 있어
  가을 갈색은 올리브색이 됐다. 지형 캡 지오메트리를 공유하는 **반투명 오버레이 메시**로 바꿨다.

  풀을 2600으로 올리고 각 날씨는 **비율(≤1.0)**로 표현하도록 바꿨다.
- **Stage D** — 추종 모델의 정지 거리가 차 길이와 거의 같아 평형점이 겹치기 직전이었다.

```

  ├ FPWorld.daySky = lerp(CLEAR_SKY, HAZY_SKY, co2k)   ← '낮의 하늘색'만 정함

```

## Stage A. 환경 합성 레이어 리팩터 (계절·날씨의 전제 — **가장 먼저**)

계절과 날씨가 둘 다 하늘색·안개·조명·온도를 건드린다. 지금 구조로는 서로 덮어써서
"비 왔다가 개면 계절 색이 사라지는" 버그가 반드시 난다. 먼저 한 곳으로 합친다.

**할 일** (`fp-world.js`)

1. `FPWorld.season = 'summer'`, `FPWorld.weather = 'clear'` 상태 추가.
2. `applyTimeOfDay()` → **`applyEnvironment()`** 로 개명·확장. 합성 순서를 고정한다:
   ```
   기준 하늘색 = daySky(CO2)
     → 계절 색조 적용 (봄 연둣빛 / 가을 노란빛 / 겨울 창백)
     → 시간 적용 (밤/황혼)
     → 날씨 적용 (흐림→회색으로 끌어당김, 안개→탁하게)
   안개 = fogFar(CO2) × 계절계수 × 날씨계수      ← 곱셈으로 합성 (덮어쓰기 금지)
   조명 = 시간계수 × 날씨계수(흐릴수록 어둡게)
   ```
3. `applyWorldCO2()` 끝의 `applyTimeOfDay()` 호출을 `applyEnvironment()`로 교체.
4. `updateTime(dt)` 안의 호출도 교체.
5. **`FPWorld.refresh()`** 를 만들어 `applyWorldCO2(FPWorld.co2)`를 부르게 하고,
   계절/날씨/시간 UI는 전부 이걸 부르게 한다 (호출 경로 하나로 통일).

**검증**: CO2 슬라이더 → 시간 슬라이더 → 계절 버튼 → 날씨 버튼을 아무 순서로 눌러도
마지막에 누른 것만 반영되는 게 아니라 넷이 모두 반영되어 있을 것.

**CO2 계절 진동이 이 기능의 과학적 핵심이다.** 실제 킬링 곡선은 북반구 식생 때문에
연 6 ppm 안팎으로 오르내린다 (5월 최고 / 9월 최저). 이미 구현된 "낮=광합성 흡수 /
밤=호흡 배출"과 정확히 같은 이야기의 연 단위 버전이라, 학생이 CO2 센서로 직접 잴 수 있다.
슬라이더 값은 '연평균'이고 실측값은 계절에 따라 흔들린다고 설명하면 된다.

기온 오프셋 근거: 중위도 연교차는 최고월−최저월 20°C 안팎. 여름 +8 / 겨울 −10 = 18°C 차.
해수 오프셋이 훨씬 작은 건 이미 구현된 `SEA_WARM_AMP=0.75`와 같은 이유(열용량).

### 구현 메모

- **비**: `THREE.LineSegments` (드롭당 정점 2개)가 `Points`보다 낫다 — 빗줄기로 보인다.
  플레이어 주위 한 변 0.6 유닛 상자 안에서만 생성하고, 상자를 매 프레임 플레이어에 붙여
  따라다니게 한다(월드 전체에 뿌리면 낭비). 아래로 떨어지다 바닥을 넘으면 위로 되돌린다.
  폭풍은 x축으로 기울인다.
- **눈**: `Points`, 크게·느리게, 좌우로 흔들리며 낙하(사인 오프셋).
- **번개**: 3~9초 간격 랜덤. `lights.ambient.intensity`를 2~3프레임 확 올렸다 되돌리고
  `skyMat.color`를 흰색으로 순간 보간. 천둥은 0.5~2.5초 뒤 (거리감) `FPAudio.thunder()`.
- **천둥 소리**: `fp-audio.js`에 추가. 갈색 잡음 버스트 + 저역통과 + 긴 감쇠(1.5~3초).
  거리에 따라 컷오프를 낮추면 멀리서 우르릉거리는 소리가 된다.
- **`frustumCulled = false`** 를 비/눈 입자에 **반드시** 설정.
  (이 저장소에서 이미 같은 함정에 두 번 걸렸다 — three.js는 boundingSphere를 생성 시점에
  한 번만 계산하고 정점을 갱신해도 다시 계산하지 않는다.)
- **랜덤 날씨**: `FPWorld.weatherRandom` 토글, 5분(300초)마다 전환.
  **기본값 off.** 시간 흐름과 같은 이유 — 조사 중에 날씨가 바뀌면 자료를 못 쓴다.
  전환은 즉시 바꾸지 말고 15초에 걸쳐 안개계수·조명계수를 보간해서 넘어가면 훨씬 자연스럽다.
- **스콜**은 지속시간이 있는 상태다. 진입 시각을 기록해 두고 2~3분 뒤 자동으로 `clear`로.

## Stage D. 자동차 주행 (요구 5)

### 현재 상태
`fp-world.js:1166` `carSpots` 12개 좌표에 **정지**해 있다. `FPWorld.boxes`에 정적 충돌체가
박혀 있고, `car.tail`은 **고정된 `Vector3`** 라서 배기가스(`updateExhaust`)와
CO2 측정(`measureCO2`)이 그 좌표를 그대로 읽는다. 움직이면 셋 다 같이 고쳐야 한다.

### 도로 월드 좌표 (계산해 둠)
```
cityGroup.position.x = +2
간선도로 : z = -0.01,  x ∈ [1.0075, 2.9925]   (길이 1.985, x축 방향)
교차도로 : x = 2.09,   z ∈ [-1.49, 1.49]      (길이 2.98,  z축 방향)
ROAD_W = 0.12  →  차선 중심선은 중앙에서 ±0.03
자동차 치수: 길이 0.09(x) × 폭 0.045(z), 바퀴 반경 0.011 → 실척 4.5m × 2.25m
```

### 설계 결정
- **총 10대** (요구사항). 간선 6대 + 교차 4대.
- 각 차는 `{ lane: 'main'|'cross', dir: +1|-1, s: 진행거리, speed }`.
  - main: 위치 = `(x = 1.0075 + s, z = -0.01 + dir*0.03)`, `rotation.y = dir>0 ? 0 : Math.PI`
  - cross: 위치 = `(x = 2.09 + dir*0.03, z = -1.49 + s)`, `rotation.y = dir>0 ? -Math.PI/2 : Math.PI/2`
    (모델이 +x를 향하고 `rotation.y=θ`면 진행방향 `(cos θ, 0, −sin θ)` → +z는 θ=−π/2)
- **끝에 도달하면 반대편 끝에서 재생성**. 속도·색(EV/내연)을 새로 뽑는다.
  재생성 시 `applyWorldCO2`가 정한 내연 비율을 지켜야 한다 → 재생성은 비율만 보고 결정.
- **속도**: 0.05~0.09 유닛/초 (실척 2.5~4.5 m/s ≈ 9~16 km/h). 미니 지구 스케일에서
  너무 빠르면 순간이동처럼 보인다. 실제로 눈으로 보고 조정할 것.
- **앞차 추종**: 같은 차선·같은 방향에서 앞차와 거리 < 0.14면 감속. ~15줄.
- **교차로**: 처음엔 그냥 통과시키고(서로 겹쳐 보일 수 있음), 눈에 거슬리면
  교차도로 차량이 `|x-2.09|<0.09 && |z|<0.09` 구간 진입 전에 간선 차량 유무를 보고 정지.
  **선택 사항** — 먼저 없이 만들어 보고 판단.
- **바퀴 회전**: `wheel.rotation.x += speed*dt/wheelR`. 바퀴 참조를 `buildCarModel`에서
  반환해야 한다(현재 안 함).

### 반드시 같이 고칠 것 (⚠️)
1. **`car.tail`을 매 프레임 갱신**. 지금은 생성 시 한 번 계산한 `Vector3`.
   `updateExhaust()`(`fp-world.js`)와 `measureCO2()`(`fp-tools.js`)가 이걸 읽는다.
   → `car.group.localToWorld(tailLocal.clone())` 을 매 프레임, 또는 위치에서 직접 계산.
2. **충돌체**. `FPWorld.boxes`의 정적 항목 대신 차마다 box 객체를 하나 만들어 두고
   매 프레임 `minX/maxX/minZ/maxZ`를 갱신. (`fp-player.js`의 `resolveCollisions`가 이 배열을 훑는다)
3. **배기 파티클 수** `EXHAUST_PER_CAR * carSpots.length` → 10대 기준으로.
4. **`FPWorld.gasCarCount`** 를 쓰는 HUD·오디오(`fp-audio.js` 도심 소음)가 그대로 동작하는지 확인.

### 검증

## Stage F. 동물 체온 이스터에그 (요구 3)

**요구는 "동물 온도 찍으면 체온"이지만, 한 걸음 더 나가면 이게 제일 좋은 교육 소재가 된다:**
포유류는 **정온동물**이라 CO2·계절·시간과 무관하게 체온이 일정한데,
**어류는 변온동물**이라 체온이 해수온과 같다. 둘을 나란히 재면 그 차이가 그대로 드러난다.
어류도 같이 넣을 것.

### 체온 표 (실제 값)
| 대상 | 체온 | 비고 |
|---|---|---|
| 토끼 | 39.0 | |
| 사슴 | 38.5 | |
| 늑대 | 38.5 | |
| 곰 | 37.5 | 겨울이면 **31.0** (동면 시 체온 강하) ← 계절 구현 후 |
| 어류 | **해수온 그대로** | 변온동물 |

정온동물은 `amp = 0`, `day = 0` (CO2·시간에 반응하지 않음)으로 두면
SPOT 테이블 구조를 그대로 쓸 수 있다. 이게 "환경이 변해도 안 변하는 값"을 보여준다.

### 구현
1. `fp-world.js` — 동물 그룹에 `group.userData.animal = a` 를 심고
   `FPWorld.animalGroups = []` 에 그룹을 모은다. 어류도 `FPWorld.fishGroups`.
   (동물은 1마리당 메시가 여러 개라 그룹 단위로 잡아야 한다)
2. `fp-tools.js` `pickTarget()` — targets에 동물/어류 그룹 추가하고
   `intersectObjects(targets, true)` (재귀 true 필요!). 맞은 객체의 조상을 타고 올라가
   `userData.animal` / `userData.fish` 를 찾는다.
3. `SPOT`에 `bodyRabbit/bodyDeer/bodyWolf/bodyBear/bodyFish` 추가.
4. `measureTemperature()`에서 어류는 `seaTemperature(ppm)` 를 그대로 반환.
5. 표시창 라벨: `°C · 토끼 체온`. 야장에도 그대로 기록된다.
6. **이스터에그다운 마무리**: 처음 동물 체온을 쟀을 때만 화면에 짧게
   "🐾 정온동물은 바깥 온도가 변해도 체온이 일정합니다" 토스트 한 번. 야장 배지 옆에.

### 검증
- 동물 조준 → 체온 표시, CO2 280↔1000 바꿔도 값 동일(오차 범위 내)
- 어류 조준 → 값이 해수온을 따라 움직임
- 동물이 움직이는 중에도 조준 가능 (raycast는 매 클릭이라 문제없음)
- 기존 8종 지점 측정이 그대로 동작 (동물을 추가해도 지형 판정이 안 깨질 것)

## 실행 순서 (계획대로 진행함)

```
A(환경 합성 리팩터)  →  B(계절)  →  C(날씨)      ← 이 셋은 순서 지킬 것
D(자동차 주행)                                    ← 독립, 언제든
E(미니맵)                                         ← 독립, 언제든
F(동물 체온)                                      ← 계절(B) 뒤에 하면 곰 동면까지 가능
```

커밋은 스테이지 단위로. A는 동작 변화가 없어야 하므로 A만 따로 커밋해서
"리팩터인데 뭔가 바뀌었다"를 바로 잡을 수 있게 한다.

**이 순서가 실제로 효과가 있었다.** A를 먼저 분리해 둔 덕에 CO₂·시간·계절·날씨가
서로 덮어쓰지 않고 곱해지는 구조가 됐고, B~C에서 순서 의존 버그가 한 건도 안 나왔다.
A는 "이전에 기록해 둔 측정값과 완전히 같은지"로 검증해서 무동작 리팩터임을 확인했다.

## 검증 환경 (매번 이렇게 했다)

```bash
# 1. 문법
node --check fp-world.js   # 등 수정한 파일 전부

# 2. 서버 (이미 떠 있으면 생략)

# 3. Playwright 로 수치 검증 + 스크린샷

```

### 이 저장소에서 이미 데인 함정 (반복 금지)

1. **`frustumCulled`** — three.js는 `boundingSphere`를 지오메트리 생성 시점에 한 번만 계산하고
   정점을 매 프레임 갱신해도 다시 계산하지 않는다. 움직이는 파티클(비·눈·배기·연기)은
   `frustumCulled = false` 또는 반경에 여유를 줄 것. **두 번 걸렸다.**
2. **헤드리스 rAF는 ~4 FPS** — 프레임 루프에 의존하는 검증은 전부 거짓말이 된다.
   물리·측정은 고정 dt로 직접 돌릴 것 (`for (i=0;i<200;i++) FPTools.update(0.05)`).
3. **측정은 이제 즉시 확정되지 않는다** — `FPTools.use()` 뒤에 `FPTools.update()`를
   `tool.reading`이 null이 될 때까지 돌려야 `lastResult`가 확정값이다.
4. **`camera.updateMatrixWorld(true)`** — 테스트에서 카메라를 순간이동시킨 뒤 raycast하면
   직전 프레임 행렬이 쓰인다. 반드시 갱신할 것.
5. **테스트 설정 실수를 버그로 오인하지 말 것** — 횡단조사 시작점을 엉뚱한 데서 잡아
   그래프가 지그재그로 나온 적이 있다. 이상하면 테스트 쪽을 먼저 의심.
6. **`git status` 먼저** — 브랜치 전환·되돌리기 전에 항상.

### 이번(Stage A~F)에 새로 데인 것

7. **재질 색은 텍스처에 곱해진다** — 흰색은 곱셈의 항등원이라 아무리 흰색으로 틴트해도
   텍스처가 그대로 보인다. 곱셈은 **어둡게만** 할 수 있어서 갈색을 섞으면 올리브가 된다.
   밝게 덮으려면 틴트가 아니라 **오버레이 메시**를 얹을 것.
8. **`PointsMaterial`은 텍스처가 없으면 사각형을 그린다** — 눈송이가 흰 네모로 나왔다.
   그리고 `size`는 월드 단위다(이 맵은 1 unit = 50 m라 `0.008`이 실척 40 cm).
   radial-gradient `CanvasTexture`를 `alphaMap`으로 줄 것.
9. **한 프레임에 `render()`를 두 번 부른다** — 월드(`fp-main.js`) + 도구 뷰모델(`fp-tools.js`).
   three.js는 `render()`마다 `info.render`를 리셋하므로, 루프 직후에 드로우콜을 읽으면
   **뷰모델의 5개만** 잡힌다. 월드 비용을 재려면 직접 `render(FPWorld.scene, camera)` 한 뒤 읽을 것.
10. **계측기 노이즈 때문에 단언이 흔들린다** — CO₂ σ=8 ppm, 온도계 σ=0.15 °C라
    한두 번 측정으로는 작은 차이를 분해할 수 없다. 판정은 **모형 함수**(`measureCO2`,
    `spotBaseTemp`)로 하고, 계측값은 느슨한 범위로 따로 확인할 것.
11. **광선이 옆 생물에 맞는다** — 동물 41마리·어류 333마리라 지형을 재려던 테스트가
    엉뚱한 걸 맞춘다. 대상 외 생물은 `visible = false`로 숨기고 잴 것.
12. **테스트의 카메라 회전 규약이 본 코드와 달랐다** — 테스트는 `camera.rotation.set(pitch, yaw, 0, 'YXZ')`를
    썼는데 실제 코드는 `camera.lookAt(eye + dir)`다. three.js 카메라는 −z를 보므로
    `rotation.set`은 **x와 z가 뒤집힌다.** 아래를 겨눌 때만 우연히 맞아서 오래 숨어 있었다.
    작은 동물을 정조준하면서 드러났다. (미니맵 부채꼴 각도는 본 코드 규약 기준으로 검산했고 정상.)
