## 이미 내려진 결정 (재논의하지 말 것)

**`T_REF = 25`를 기본값으로 유지하고, HOT 관측 RMSE가 0.0070 → 0.0084로 나빠지는 것을 받아들인다.**

- 25 °C는 HOT(하와이 ALOHA) 관측 해역의 실제 표층 수온이다.
- RMSE를 되돌리려고 `T_REF`를 18~20 °C로 내리면 숫자는 좋아지지만(0.0070),
  그건 **관측에 맞춰 기준 수온을 고르는 것**이라 이 모형의 핵심 주장인
  *"회귀로 맞춘 게 아니라 문헌 화학 상수만 넣었는데 관측과 겹친다"*와 정면으로 충돌한다.
- 따라서 **`T_REF`를 관측에 맞추는 방향으로 조정하는 것은 금지한다.** 대신 문서의 수치를 고친다.

## A. P0-1 — 미래 예측 탭 바다 색 버그

**현상:** `js/tab-future.js`의 `co2slider` 입력 핸들러가 `sceneFuture.state.co2`만 갱신한다.
물 색·탁도·투명도를 결정하는 `state.ph`는 초기값 `8.04`(`js/common.js`의 `state` 리터럴)에
고정돼 있어서, CO₂를 1000 ppm으로 올려도 바다가 그대로다.
(`js/common.js`의 `applyState`에서 `phIntensity`가 `state.ph`로만 계산된다.)

**수정:** 핸들러에서 `applyState(sceneFuture)` **앞에** 한 줄을 넣는다. `p`는 이미 위에서 계산돼 있다.

```js
sceneFuture.state.ph = p;   // 해양 산성화가 물 색에 반영되도록
```

## B. 변경 1 — 온도 의존 탄산 평형 (`js/earth-model.js`)

`10.09변경사항정리.md` 3.2절의 코드를 그대로 적용한다. 요점:

- `carbonateConstants(tC, S)` 신설 — K₀는 Weiss(1974), K₁·K₂는 Lueker et al.(2000) total scale,
  Ksp(아라고나이트)는 Mucci(1983). 염분 S = 35 고정.
- `seawaterState(ppm, tC = 25, TA = OCEAN_TA)` 신설 — pH, `co2aq`, `hco3`, `co3`, `dic`, `omega`를
  한 번에 돌려준다.
- **기존 이름을 반드시 유지한다:** `seawaterPH(ppm, tC = 25)`, `aragoniteOmega(ppm, tC = 25)`.
  기본 인자 덕에 **기존 호출부는 한 줄도 고치지 않아도 동작해야 한다.**
  (호출부: `js/tab-future.js`, `js/common.js`, `firstperson/fp-world.js`, `firstperson/fp-tools.js`)
- 하드코딩돼 있던 `OCEAN_K0` / `OCEAN_K1` / `OCEAN_K2` / `ARAGONITE_KSP` 상수는 제거하거나,
  남긴다면 더 이상 쓰이지 않음을 주석으로 명시한다.
- 파일 상단 주석의 "RMSE 0.007" 설명도 0.008로 고치고, **왜 25 °C를 쓰는지**를 한 줄 적는다.

## 합격 기준 — 전부 통과해야 한다

검증 스크립트가 이미 저장소에 있다. **반드시 저장소 루트에서** 실행한다(상대 경로를 쓴다).

```bash
python Critical_Earth_simulator/tools/verify_carbonate_proposal.py
```

이 스크립트는 "제안식"을 자체 구현해 기준값을 뽑는다. 구현을 끝낸 뒤에는
**실제 `js/earth-model.js`가 같은 값을 내는지**도 따로 확인해야 한다(아래 2번).

1. **스크립트 기준값 재현** — 체크 3의 3×4 표가 `!` 표시 없이 전부 재현될 것.
2. **실제 구현 대조** — node로 `js/earth-model.js`를 읽어 아래가 성립할 것:
   - `seawaterPH(ppm, 25)`가 280~1000 ppm 전 구간에서 스크립트의 `state(ppm,25)['pH']`와 **0.0005 이내**
   - `seawaterPH(418, 2)` ≈ 8.025, `seawaterPH(418, 25)` ≈ 8.042
   - `aragoniteOmega(418, 25)` ≈ 3.51 (기존 3.43에서 바뀌는 게 정상)
   - `aragoniteOmega(1000, 2)` ≈ 0.69 (**1 미만** — 냉수대에서 경고가 켜질 수 있다는 뜻)
3. **하위 호환** — `seawaterPH(418)`, `aragoniteOmega(418)`처럼 **인자 하나로 부르는 기존 호출이
   그대로 동작**할 것. 기존 호출부 파일을 수정하지 않았을 것.
4. **문법** — 고친 js 전부 `node --check` 통과.
5. **두 모드 일치** — 조감·1인칭이 280/418/600/1000 ppm에서 같은 pH·Ω를 낼 것
   (같은 `earth-model.js`를 읽으므로 자동으로 성립해야 하지만, 깨지지 않았는지 확인할 것).
6. **단일 HTML 빌드** — `python Critical_Earth_simulator/tools/build_single_html.py`가 성공할 것.
   (`vendor/`가 커밋돼 있어 인터넷 없이 된다.)
7. **P0-1 확인** — 미래 예측 탭에서 CO₂ 280 → 1000일 때 `sceneFuture.state.ph`가 실제로 바뀔 것.

### 알아둘 것 (헛걸음 방지)

- RMSE가 0.0084로 나오는 것은 **정상이고 의도된 결과**다. 이걸 "실패"로 보고 상수를 만지지 말 것.
- 헤드리스 브라우저의 rAF는 ~4 FPS라 프레임 루프에 의존하는 검증은 거짓말이 된다.
  판정은 순수 함수 계산으로 할 것.
- Playwright가 깔려 있지 않으면 설치해도 되지만, **필수는 아니다.** 위 1~7은 전부
  node/python만으로 판정할 수 있다.

## 브랜치와 마무리

- 기준 브랜치는 `feature/first-person-mode`다 (`main`이 아니다).
