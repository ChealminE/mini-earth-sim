# 3차 D — 미래 예측 구조 일관화

> 마스터 규칙을 따른다. 마스터 결정 9: **조작하는 것은 배출 경로, CO₂는 그 결과(매개), 기온·해수온·pH는 최종 결과.**
> 엔진(`earth-system.js` 머리 주석)이 이미 이렇게 설계돼 있다 — "CO2를 '입력'이 아니라 배출을 적분한 '결과'로 바꾼다".
> 화면과 문구가 이 구조와 어긋나는 곳만 고친다. **새 탐구 기능은 만들지 않는다.**

## 0. 하지 않는 것 (사람이 버린 안)

- CO₂ 농도를 x축으로 두고 기온·해수온·pH를 그리는 "변인 간 직접 관계" 보기 — **만들지 않는다.**
  기온은 로그 강제력과 심층해양 지연 때문에 같은 ppm에서도 경로마다 값이 달라(예: SSP1-1.9 정점 이후) "시나리오와 무관한 일정한 비례"가 성립하지 않는다.
- CO₂를 직접 정하는 슬라이더·농도 고정 모드 — 2차에서 이미 없앴다. 되살리지 않는다.

## 1. D1 — 원인 → 매개 → 결과 표기

1. **조작 띠(B1)의 시나리오 묶음에 머리말** "① 배출 경로 고르기"를 단다. 직접 설계 패널 머리말도 "① 배출 경로 직접 설계".
2. 시나리오 버튼 옆에 **고른 경로의 배출량 작은 선**(1750~2200, 화석+토지이용, GtC/yr)을 그린다.
   - C2의 스파크라인 함수를 쓴다(Chart.js 인스턴스 추가 금지). C가 아직이면 같은 모양의 2D 캔버스 함수를 `graph-workspace.js` 에 먼저 만들어 둔다.
   - 재생 중에는 지금 연도까지 진하게, 이후는 옅게(시간 막대와 같은 과거/예측 표현). 값은 `EarthSystem.run` 결과의 `emissions` 를 그대로.
   - ⓘ는 시나리오 배출 출처(등록부의 SSP 배출 키, 직접 설계면 레버 키).
3. 그래프 칸 머리에 한 줄: **"배출 → ② 대기 CO₂ → ③ 기온 · 해수온 · pH"**. 그래프 제목 앞에 같은 번호(② / ③)를 붙인다.
   CO₂ 그래프 제목 보조 문구 "배출이 쌓인 결과".
4. 직접 설계 결과 문구(`#lvResult`)가 CO₂·기온을 먼저 말하고 있으면 "배출 ○○ GtC/yr → 2100년 CO₂ ○○ ppm, 기온 ○○ °C" 순서로 바꾼다.

## 2. D2 — 문구 점검

아래로 찾아 **원인이 CO₂인 것처럼 조작을 지시하는 문구**만 고친다. CO₂가 기온의 원인이라는 설명(CO₂ → 기온)은 맞으므로 그대로 둔다.

```
grep -rn "조작변인\|독립변인\|변인 1\|CO₂를 올\|CO₂를 높\|CO₂를 바꾸\|농도를 정\|농도를 바꾸\|농도를 올" \
  Critical_Earth_simulator/index.html Critical_Earth_simulator/js/inquiry-steps.js Critical_Earth_simulator/js/tab-future.js \
  Critical_Earth_simulator/js/sources.js Critical_Earth_simulator/select.html
```

- 고친 예: "CO₂를 높여 보세요" → "배출이 많은 경로를 골라 보세요". "CO₂가 더 높아지면?" 같은 **질문 제목**은 결과를 묻는 것이므로 그대로 둔다.
- `inquiry-steps.js` 문구를 고치면 고친 단계 id와 전·후 문구를 세이브포인트 메모에 표로 남긴다(수업 담당자가 확인해야 함).
- 직접 실험 탭·1인칭 문구는 여기서 고치지 않는다(1인칭은 E4).
