# 1차 대격변 — 지구 시스템 엔진 + 조감 모드 타임라인

> **이 파일이 마스터다.** 순서·규칙·수용 조건이 전부 여기 있다.
> 참조 구현은 `Critical_Earth_simulator/tools/earth_system_ref/engine.py`, 데이터는 `Critical_Earth_simulator/data/`.

## 0. 무엇을 바꾸나

지금 앱은 **CO₂를 사람이 슬라이더로 넣고, pH·기온을 그 자리에서 평형값으로 계산**한다.
이번 작업은 이것을 **"인간활동 → 배출 → 탄소순환 → 대기 CO₂ → 나머지 변수"가 시간에 따라 굴러가는 구조**로 바꾼다.

설계 원칙 (전 단계 공통):

- **CO₂가 주축이다.** 외부에서 바꿀 수 있는 것은 배출(인간활동 레버)과 계절뿐이다.
  pH·기온·해수온·Ω는 엔진이 계산한 종속 변수이며, 이것들을 직접 바꾸는 슬라이더를 만들지 않는다.
- **피드백은 남긴다.** 기온 → 해수 CO₂ 용해도(K₀), 기온 → 토양 호흡(Q10)은 다시 CO₂에 영향을 준다.
- **두 개의 지구.** 같은 엔진을 "자연만(배출 0)"과 "인간활동"으로 각각 돌려 1750년부터 갈라지게 한다.
- 대상은 **고등학생**이다. 화면 용어는 고등학교 화학·지구과학 수준으로 쓴다
  (예: Revelle 계수는 "바다의 완충 능력"으로 표시하고, 용어 설명에서만 이름을 언급).

이번 범위는 **1단계(엔진)와 2단계(조감 UI)** 다. 1인칭 모드는 이번에 건드리지 않는다.

### 1단계 — 참조 구현 보정값 갱신 + 데이터 JS 생성

```
c0 = 278.0, tau_mix = 6.0, h_deep = 2000.0, beta = 0.38, tau_land = 50.0, k_gas = 0.25
(나머지 h_mix=100, npp0=60, q10=2.0, lam=1.2, Cs=8.0, Cd=100.0, gamma=0.7, sst0=18.0 는 그대로)
```

- `engine.py` 의 `P` 기본값을 위 값으로 바꾸고, `scen.py` 의 `p.update(...)` 줄도 같은 값으로 맞춘다.

### 2단계 — `earth-model.js` 순수 함수 추가

기존 함수와 상수는 **값도 이름도 바꾸지 않는다.** 1인칭 모드가 그대로 쓰고 있다. 추가만 한다.

- `pco2FromDic(dic, tC, TA = OCEAN_TA)` → `{pco2, pH, omega, co2aq, hco3, co3}`
  `engine.py` 의 `pco2_from_dic` 과 같은 식(`TA·h² + (TA−DIC)·K1·h + (TA−2·DIC)·K1·K2 = 0`).
  `seawaterState` 와 같은 탄산염 알칼리도 가정(붕산염 없음)을 유지한다.
- `radiativeForcing(ppm, c0)` = `5.35 · ln(ppm / c0)` [W/m²]
- `revelleFactor(ppm, tC)` — `engine.py` 의 `revelle` 과 같은 수치미분.
- `bufferCapacityRel(ppm, tC, refPpm, refTC)` = `revelleFactor(ref) / revelleFactor(now)`.
  화면에는 **이 상대값(1750 대비 %)만** 쓴다. 붕산염을 뺀 모형이라 Revelle 절댓값(12~20)은 실제(약 10)보다 높게 나오기 때문이다. 이 이유를 함수 주석에 적는다.
- `climateAnomaly()`·`warmingSince280()` 위에 주석 추가:
  "1인칭 모드 전용으로 남겨 둔 회귀식. 조감 모드는 js/earth-system.js의 2층 에너지 균형 모델을 쓴다. 3단계(1인칭 연동)에서 교체 예정."

**수용 조건**: 기존 수치 불변. 25 °C에서 pH 8.184 / 8.042 / 7.908 / 7.710, Ω 4.54 / 3.51 / 2.72 / 1.82 (280/418/600/1000 ppm).
`pco2FromDic(seawaterState(p, t).dic, t).pco2` 가 `p` 와 상대오차 1e-9 이내 (p = 280, 418, 1000 / t = 2, 18, 25).

### 3단계 — 엔진 이식 + 대조 테스트 【게이트 A】

`js/earth-system.js` 를 새로 만든다. DOM·three.js·Chart.js를 쓰지 않는 순수 모듈이다. 기존 파일들처럼 전역 스크립트로 쓴다.
로드 순서는 `earth-model.js` → `earth-data.js` → `earth-system.js`.

**이식 원칙: `engine.py` 의 `run()` 을 한 줄씩 그대로 옮긴다.** 갱신 순서까지 같아야 한다.
dt = 0.25년 고정이다. 각 하위 단계에서 아래 순서를 지킨다.

1. 시작 시점의 ppm으로 모든 플럭스를 계산
2. 대기 → 토양 → 표층 → 심층 순으로 갱신
3. 기온 T, Td 갱신

결과가 dt에 의존하므로 dt를 바꾸지 마라.

- 상태: `{year, atmC, dicSurf, dicDeep, landC, T, Td}` + 누적 플럭스(대기 증가, 해양 흡수, 토양 흡수, 누적 배출).
- `EarthSystem.run({fromYear:1750, toYear:2200, emissionsFn})` → 연도별 배열.
  각 원소는 `{year, ppm, T, sst, pH, omega, co2aq, hco3, co3, dic, bufferRel, oceanFlux, landFlux, emissions, cum:{atm, ocean, land, emitted}}`.
- `sst = sst0 + T` (참조 구현과 동일). 대기 기온은 전 지구 평균 편차 T를 그대로 쓴다.
  육상 증폭(×1.4 등)은 이번에 넣지 않는다.
- 해수 화학은 반드시 `earth-model.js` 의 함수를 호출한다. 식을 다시 쓰지 마라.

**대조 테스트** `tools/test_earth_system.js` (node). `vm` 모듈로 `earth-model.js`, `earth-data.js`, `earth-system.js` 를 순서대로 한 컨텍스트에 불러와 실행한다.

- 같은 입력에서 `engine.py` 결과와 대조한다. 1750~2200 모든 연도에서 |Δppm| < 0.05, |ΔT| < 0.005, |ΔpH| < 0.0005, |ΔΩ| < 0.005.
  파이썬 쪽 결과는 `engine.py` 에 JSON 덤프 옵션을 추가해 만든다.
- 1단계 기대값 표를 JS 결과로도 재현한다.
- 자연 지구(배출 0): 1750~2200 내내 278.0 ± 0.1 ppm, T = 0 ± 0.01.

**게이트 A**: 위 세 가지가 전부 통과해야 4단계로 간다.

### 4단계 — 레버·프리셋·농도 고정 모드 【게이트 B】

**(a) 프리셋 시나리오** (인간활동 지구용). 2023년까지는 항상 역사 배출량이고, 2024년부터 아래 경로를 따른다.
**`scen.py` 의 정의와 똑같아야 한다.**

| 프리셋 | 2024년 이후 배출 |
|---|---|
| 현재 추세 | 화석 = E₂₀₂₃ × (1 + 0.01·(y−2023)), 2100년 이후 E₂₀₂₃ × 1.77 고정 / 토지이용 = L₂₀₂₃ × max(0, 1 − (y−2023)/80) |
| 파리협약 | 화석·토지이용 모두 2023년 값에서 2075년 0까지 선형 감소 |
| 2050 탄소중립 | 화석·토지이용 모두 2023년 값에서 2050년 0까지 선형 감소 |

기대값 (보정값 적용 후 `scen.py` 출력, JS가 같은 값을 내야 함):

| | 2050 | 2100 | 2200 |
|---|---|---|---|
| 현재 추세 | 495 ppm, +1.73 °C | 702 ppm, +2.89 °C, pH 7.857 | 1269 ppm, +5.16 °C, Ω 1.41 |
| 파리협약 | 451 ppm, +1.52 °C | 415 ppm, +1.44 °C | 399 ppm, +1.42 °C |
| 2050 탄소중립 | 422 ppm, +1.38 °C | 383 ppm, +1.17 °C | 375 ppm, +1.19 °C |

**(b) 직접 설계 모드 (레버 6개).** 레버 값은 **2050년 목표**다.
2024년의 현재값에서 2050년 목표까지 선형으로 바뀌고, 2050년 이후에는 목표값을 유지한다.

```
화석 배출(t) = E₂₀₂₃ × [ s_power·P(t) + s_road·R(t) + s_other·(1 − 기타감축(t)) ] − 탄소포집(t)
  P(t) = 화석발전비중(t) / f₀
  R(t) = [ (1 − ev(t)) + ev(t)·k_ev·(화석발전비중(t) / f₀) ] / [ (1 − ev₀) + ev₀·k_ev ]
토지이용 배출(t) = 산림 레버 (+L₂₀₂₃ = 벌채 지속 … 0 = 벌채 중단 … −1.0 GtC/yr = 대규모 조림)
```

| 기호 | 값 | 비고 |
|---|---|---|
| s_power, s_road, s_other | 0.40, 0.16, 0.44 | 2023년 화석 CO₂ 중 발전·도로수송·기타 비중 (대략치) |
| f₀ | 0.61 | 2023년 전력 중 화석 비중 (대략치) |
| 원자력 / 재생 현재값 | 0.09 / 0.30 | 세 비중의 합은 항상 1 |
| ev₀ | 0.03 | 보유 차량 중 전기차 비율 (대략치) |
| k_ev | 0.45 | 2023년 전력망에서 전기차의 km당 배출 / 내연기관차 (대략치) |
| 탄소포집 | 0 ~ 3 GtC/yr | 현재값 0 |
| 기타감축 | 0 ~ 100 % | 현재값 0 |

- **표의 "대략치"는 IEA·Ember 등 공개 자료로 확인해서 코드 주석에 출처와 연도를 적는다.**
  확인하지 못한 값은 그대로 쓰되 주석에 `미확인` 이라고 표시하고 PR에 목록으로 남긴다. 수치를 지어내지 마라.
- 원자력과 재생은 이 식에서 배출이 같다(둘 다 0). 버그가 아니라 의도다. 화면 설명에 "CO₂ 배출만 보면 같다"고 적는다.
- **현재값 그대로**면 2024년 이후 배출이 2023년 값으로 일정해야 한다(오차 0.1% 이내). 이게 레버 식의 검증이다.

**(c) 농도 고정 모드.** 2023년까지는 역사 배출량으로 진행하고, 2024년부터 대기 CO₂를 프리셋 값(280/418/560/800/1000)에 고정한다.
대기는 적분하지 않고, 해양·토양·기온은 그 농도에서 계속 적분한다. `engine.py` 에 `run_fixed(ppm)` 를 추가해 같은 규칙으로 구현하고 JS와 대조한다.

| 고정 농도 | 2030 | 2100 | 2200 | (평형 기온) |
|---|---|---|---|---|
| 418 | +1.26 °C, pH 8.052 | +1.42 °C | +1.56 °C | 1.82 |
| 560 | +1.94 °C, pH 7.946 | +2.37 °C | +2.63 °C | 3.12 |
| 1000 | +3.28 °C, pH 7.721 | +4.25 °C | +4.76 °C | 5.71 |

이 표가 보여주는 핵심("pH는 바로 따라가고 기온은 수백 년에 걸쳐 따라간다")을 5단계 화면 설명에 쓴다.

**게이트 B**: 프리셋 3개와 농도 고정의 JS·파이썬 대조, 레버 현재값 = 일정 배출 검증이 전부 통과.

**→ 여기서 커밋하고 세션 작업 브랜치에 한 번 push 한다.** 이후 단계가 막혀도 검증된 엔진은 남는다.

### 5단계 — 미래 예측 탭을 타임라인으로 (단일 지구)

미래 예측 탭을 **1750~2200 타임라인**으로 바꾼다. 우선 인간활동 지구 하나로 완성한 뒤 6단계에서 분할한다.

- **궤적은 미리 계산한다.** 프리셋이나 레버가 바뀌면 `EarthSystem.run` 을 다시 돌려 배열을 만들고,
  재생은 배열을 인덱싱만 한다(연도 사이는 선형 보간). 렌더 루프 안에서 엔진을 돌리지 마라.
- **재생 조작**: 재생/일시정지(기본 10년/초), 연도 점프 버튼 6개(1750 산업혁명 이전 / 1850 / 1950 / 2023 현재 / 2100 / 2200), 타임라인 스크러버.
- **그래프** (Chart.js, x축 = 연도 1750~2200, 재생 위치에 세로선):
  1. 대기 CO₂ (+ `EARTH_DATA.mlo` 관측점, "마우나로아 관측"으로 표시)
  2. 기온 편차 (산업화 이전 대비)
  3. 해수 pH, Ω (Ω = 1 기준선 표시)
  4. **"배출된 탄소는 어디로 갔나"**: 재생 연도까지의 누적 배출을 대기 / 해양 / 토양으로 나눈 누적 막대
- **y축을 하드코딩하지 마라.** 현재 추세는 2150년 무렵 1000 ppm을 넘는다(2200년 1269).
  축 범위는 데이터에서 계산한다. 공유 상수 `CO2_MAX`(1000)는 **바꾸지 마라.** 1인칭이 쓴다. 3D 효과 강도만 1000에서 포화되면 된다.
- **결과 카드**: 재생 연도의 CO₂, 기온, 해수온, pH, Ω, 바다의 완충 능력(1750 대비 %).
- **기존 화학종 분포 막대·완충 설명은 유지**하고, 재생 연도의 엔진 값(`co2aq/hco3/co3`)에 연결한다(기준은 1750년).
- **기존 산점도 2개(CO₂ vs 기온 회귀선, CO₂ vs pH)는 미래 예측 탭에서 뺀다.** 회귀식 외삽은 새 엔진과 다른 답을 낸다.
  관측 상관을 보여주는 용도로 현재 실태 탭에 옮기는 것은 11단계에서 판단하고, 옮긴다면 외삽선 없이 관측점만 둔다.
- 3D는 재생 연도의 엔진 값으로 `applyState` 를 부른다: `state.co2 = ppm`, `state.ph = pH`, 빙하 축소는 T로.
  기존 매핑 상수(`CO2_MIN/MAX`, `PH_MIN/MAX`)는 재사용한다. 상태 갱신은 0.2초 틱으로 하고, 매 프레임 하지 않는다.

### 6단계 — 두 지구 분할 렌더

- 미래 예측 탭에서만 아크릴을 좌우로 둔다. 왼쪽은 "자연만 있는 지구"(배출 0), 오른쪽은 "인간활동 지구".
  한 렌더러에서 `setScissor`/`setViewport` 로 두 씬을 그리고, 카메라 하나를 공유해 회전·줌을 동기화한다.
- 씬은 기존 `sceneFor()` 방식으로 지연 생성한다. 다른 탭은 지금처럼 하나만 그린다.
- **자연 지구 표현**: 도시 구역의 건물·자동차·공장·도로·포집 타워를 숨긴다(지면은 그대로).
- 각 지구 위에 이름표와 현재 CO₂·기온을 작게 표시한다.
- 성능: 분할 상태의 드로우콜을 측정해 PR에 적는다. 단일 대비 2배 이내면 정상이다.

### 7단계 — 인간활동 레버 UI + 3D 반영

- 오른쪽 지구용 패널: 프리셋 버튼 3개(현재 추세 / 파리협약 / 2050 탄소중립)와 [직접 설계] 하나.
  [직접 설계]를 누르면 레버 6개가 열린다. 전력 구성은 화석/원자력/재생 합이 100%가 되는 한 덩어리 조작으로 만든다.
- 레버는 **2024년 이후에만** 적용된다고 화면에 적는다. 재생 중에 바꾸면 궤적을 다시 계산하고 재생 위치는 유지한다.
- 3D 반영 (기존 오브젝트 재사용 우선):

| 레버 | 3D |
|---|---|
| 전기차 비율 | 기존 자동차 색 (`state.ev`) |
| 화석 발전 비중 | 기존 공장 연기 (`state.fossil`) |
| 원자력 비중 | **새 메시**: 냉각탑 (도시 구역, 비중에 따라 크기·표시) |
| 재생 비중 | **새 메시**: 태양광 패널 (도시 구역 지붕·빈 땅, 비중에 따라 개수) |
| 탄소포집 | 기존 포집 타워 (`state.carbonRemoval`) |
| 산림 | 기존 나무 수 (조림이면 늘고 벌채면 줄어듦) |

- 3D는 레버 목표값이 아니라 **재생 연도의 실제 레버 값**(선형 전환 중의 값)을 보여준다.

### 8단계 — 농도 고정 모드 UI

- 타임라인 패널 상단에 [시나리오 | 농도 고정] 전환 버튼을 둔다.
- 농도 고정: 프리셋 버튼 280 / 418 / 560 / 800 / 1000 ppm. 고르면 2024년부터 오른쪽 지구의 농도를 고정하고, 재생으로 수렴 과정을 보여준다.
- 설명 한 줄: "pH는 바로 바뀌지만, 바다가 데워지는 데는 수백 년이 걸려서 기온은 천천히 따라간다." (4단계 표 근거)
- 280을 고르는 것은 "지금 당장 산업화 이전 농도로 되돌린다면?"이라는 사고실험이라고 표시한다(현실의 경로가 아님).

### 9단계 — 계절 선택기 (조감 최소 이식)

- `earth-model.js` 에 `SEASON_CLIMATE` 를 추가한다: 봄/여름/가을/겨울별 `{ko, temp, seaT, co2, ice}`.
  **값은 `firstperson/fp-world.js` 의 `SEASONS` 와 똑같이 복사한다.** `fp-world.js` 는 수정하지 않는다.
  두 곳에 같은 값이 생기므로, 양쪽에 "3단계에서 하나로 합칠 것" 주석을 단다.
- 조감에 계절 선택기를 둔다. **재생 중 자동으로 바뀌지 않는 "관측 계절"** 이다(10년/초 재생에서 계절이 깜빡이면 의미가 없다).
- 계절이 바꾸는 것: 표시 CO₂ (+ 계절 진동, 엔진 입력은 아님), 표시 기온·해수온 오프셋, 빙하 크기(`ice` 배수), 나뭇잎 색.
  지면 눈은 선택 사항이다. 넣는다면 반드시 오버레이 메시로 한다(재질 틴트로는 밝아지지 않는다).
- 화면에 "엔진은 연평균으로 계산하고, 계절은 그 위에 얹는 관측 시점의 차이"라고 설명한다.

### 10단계 — 측정 패널 (측정 요소 4개)

- 프로그램 전체의 공통 측정 요소 4개를 쓴다: **대기 CO₂ (ppm) · 기온 (°C) · 해수온 (°C) · 해수 pH**.
- 게이지 4개를 자연 | 인간 두 열로 나란히 보여준다. 값은 재생 연도와 관측 계절을 반영한다.
- [기록] 버튼을 누르면 표에 한 줄을 추가한다(연도, 계절, 시나리오/고정값, 지구, 측정 요소 4개).
  [CSV 내보내기]는 엑셀 한글 깨짐 방지를 위해 BOM을 붙인다(기존 코드 방식 재사용).
- 열 이름은 `co2_ppm, air_temp, water_temp, ph` 로 한다. 직접 실험 탭과 1인칭 야장도 나중에 이 이름으로 맞출 예정이다.

### 11단계 — 현재 실태 탭: 모형 선 겹치기

- CO₂ 추이 그래프에 엔진의 역사 실행 결과(1988~2023)를 점선으로 겹친다. 범례: "관측(지구 평균)" / "모형".
- **기온 그래프에는 아직 겹치지 마라.** 기존 `histTemp` 의 기준 기간이 확인되지 않았다(주석상 1991~2020 평년이지만,
  2023년 값 0.837이 주요 데이터셋의 1991~2020 기준 값과 맞지 않는다). 출처를 확인하지 못하면 PR에 "미확인"으로 남긴다.
- 산점도를 옮긴다면(5단계 참고) 외삽선 없이 관측점만 둔다.

### 12단계 — 문구·빌드·문서 정리

- 미래 예측 탭 안내문(`index.html` 의 `co2slider` 아래 `p.hint`)을 새 구조에 맞게 다시 쓴다.
  특히 **"이 슬라이더 값은 왼쪽 3D 씬과 1인칭 탐험 모드에도 똑같이 반영됩니다" 는 삭제한다**(사실이 아님, P0-4).
  "기온편차는 log₂ 형태로 회귀" 서술도 이제 조감 모드에는 맞지 않으므로 2층 에너지 균형 모델 설명으로 바꾼다.
- 새 JS 파일(`earth-data.js`, `earth-system.js`)을 `index.html` 의 `<script>` 순서와 `tools/build_single_html.py` 의 `AERIAL_JS` 목록 **양쪽에** 같은 순서로 넣는다.

## 5. 작업 방식

**한 단계씩, 단계마다 커밋한다.** 커밋 메시지는 `대격변 3단계: 엔진 이식 + 대조 테스트` 형식으로 쓴다.

### 막혔을 때

- **수치를 억지로 맞추지 마라.** 특히 보정 파라미터를 몰래 바꾸지 마라. 기대값과 다르면 실제 출력과 함께 보고한다.
- 게이트 A·B에서 막히면 → **멈춘다.** 5단계 이후를 하지 않는다.
- 5단계 이후에서 막히면 → 의존 관계(§1 "선행" 열)를 보고, 의존하지 않는 다음 단계로 넘어간다.
  예: 6단계가 막혀도 7·8·10·11은 할 수 있다. 무엇이 왜 안 됐는지 기록한다.

### 이 저장소에서 이미 데인 함정

1. **Chart.js 축 하드코딩 금지** — 예전에 `max: 600` 을 박아서 곡선이 그래프 밖으로 나갔다. 이번엔 1269 ppm까지 간다.
2. **헤드리스 rAF는 약 4 FPS** — 프레임 루프에 의존한 검증은 거짓말이 된다. 엔진은 node에서 함수로 직접 검증한다.
3. **재질 색은 텍스처에 곱해진다** — 흰색 틴트로는 밝아지지 않는다. 눈·밝은 덮개는 오버레이 메시로 한다.
4. **움직이는 파티클은 `frustumCulled = false`** — 바운딩 구가 생성 시 한 번만 계산된다.
5. **`build_single_html.py` 목록과 `index.html` 스크립트 순서가 다르면 빌드가 일부러 멈춘다** — 둘 다 고칠 것.
6. **공유 상수 `CO2_MIN/CO2_MAX` 는 1인칭도 쓴다** — 값을 바꾸면 1인칭이 조용히 바뀐다.
7. **테스트 설정 실수를 버그로 오인하지 마라** — 이상하면 테스트 쪽을 먼저 의심할 것.

## 6. 마무리

- 세션 작업 브랜치에 push 하고 **`main` 대상 PR을 연다. 병합하지 마라.** force push를 하지 않고, 다른 브랜치로 push하지 않는다.
- PR 맨 위에 **어디까지 했고 어디서 왜 멈췄는지** 한 문단으로 요약한다.
- 본문에는 "통과했다"가 아니라 **실제 출력 숫자**를 적는다:
  - 게이트 A: JS·파이썬 최대 차이(ppm, T, pH, Ω), 1단계 기대값 표 재현 결과, 자연 지구 범위
  - 게이트 B: 프리셋 3개 × 2050/2100/2200 표, 농도 고정 표, 레버 현재값 일정 배출 오차
  - 레버 상수 출처 목록과 `미확인` 항목
  - 분할 렌더 드로우콜 (단일 vs 분할)
  - 스크린샷 (타임라인 1750/2023/2200, 분할, 레버 패널, 측정 패널)
  - 기온 기준선(`histTemp`) 확인 결과
