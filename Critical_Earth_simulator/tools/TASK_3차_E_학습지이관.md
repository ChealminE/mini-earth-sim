# 3차 E — 학습지 이관 · 1인칭 연동

> 마스터 규칙을 따른다. 이 단계의 목적:
> ① 탐구 과제를 우측 학습지에서 진행하고, ② 화면에서 내린 기능 여섯 개를 학습지에서 켜고, ③ 탐구 경로를 맞는 탭으로 옮기고, ④ 1인칭과 연결한다.
> 구조 원칙은 2차 E 그대로: **단계는 데이터(`inquiry-steps.js`), 실행기는 `inquiry.js`, 단계는 선언형**(들어갈 때마다 기본 상태로 되돌리고 actions만 적용).

## 1. E1 — 탐구 실행기를 학습지로

1. 새 파일 `js/worksheet.js`: 학습지 패널(B2)의 탭 전환·접기·카드 영역과 **공용 저장소**.
   - 저장소 키 `worksheet.v1` = `{ answers: {pathId: {saveAs: 값}}, evidence: [...], fp: {...}, ui: {...} }`.
   - 처음 읽을 때 `inquiry.v1`(2차 E5)이 있으면 **한 번 옮겨 담는다.** 옛 키는 지우지 않는다(되돌리기 대비).
   - 모든 읽기·쓰기 try/catch(마스터 §6-8). index.html·빌더 `AERIAL_JS` 둘 다에 추가(`inquiry.js` 앞).
2. `inquiry.js` 가 단계 화면을 `#inqPanel` 대신 학습지 [탐구] 탭에 그리게 한다(B2에서 DOM을 옮겼다면 id 그대로라 수정이 적어야 한다).
   `InquiryCore`(DOM 없는 부분)는 건드리지 않는다.
3. 경로에 **`tab: 'current' | 'future'`** 필드를 추가한다. 학습지는 지금 탭의 경로만 목록에 보인다.
   탐구 중에 다른 탭으로 가면 학습지에 "이 탐구는 ○○ 탭에서 이어집니다 [돌아가기]"를 띄우고 단계 상태는 유지.
4. 자유 조작 모드의 [탐구] 탭에는 경로 목록 아래 **"보기 도구"** 묶음(E2의 여섯 기능 버튼)을 둔다 — 탐구 경로 밖에서도 기능에 닿을 수 있게.

## 2. E2 — 이관된 보기 기능

### 새 동작 (`ACTION_SPEC` 과 `inquiry-steps.js` 머리 주석의 동작 목록에 함께 추가)

| 동작 | 형식 | 하는 일 | 탭 |
|---|---|---|---|
| `view3d` | `{ do: 'view3d', mode: 'co2' \| 'indicator' \| 'visible' }` | B3에서 숨긴 3D 보기 토글 함수를 부른다. `'ir'` 은 F에서 추가 | 둘 다 |
| `card` | `{ do: 'card', id: 'legend3d' \| 'spec' \| 'omega' \| 'sink' \| 'impacts' }` | 학습지 카드 영역에 해당 카드를 연다 | 둘 다(아래) |
| `ws` | `{ do: 'ws', load: ['co2','fossil'], mode?: 'time', range?: 'all', lock?: true }` | 그래프 작업대(C) 상태를 정한다. `lock` 이면 그 카드만 덱에 보이게 | current |
| `askEvidence` | `{ do: 'askEvidence', saveAs, prompt, need?: ['co2','fossil'] }` | [나의 증거]에서 하나를 고르거나 지금 작업대를 붙이고 주장 한 줄을 쓰게 한다 | 둘 다 |

- 기존 `toggleNature`·`openPopover`·`omega` 는 **그대로 남기고** 동작도 그대로(기능 유지). `openPopover: spec` 은 내부적으로 `card: spec` 을 부르게 해도 된다.
- 단계 기본 상태로 되돌릴 때 `view3d`·`card`·`ws` 도 되돌린다(선언형 원칙). 학생이 작업대에 직접 넣은 자료는 자유 조작으로 돌아가면 복원(`ws.getConfig/loadConfig`).

### 학습지 카드 (DOM 이동으로 만든다 — 갱신 코드가 id로 찾으므로)

| 카드 | 원래 요소 | 주의 |
|---|---|---|
| `legend3d` | `#legend3d` | `view3d: indicator` 가 켜지면 **자동으로** 이 카드를 연다(지시약 색을 읽으려면 범례가 필요) |
| `spec` 바다 속 탄소 | `#popSpec` 안 내용 | 갱신 조건이 `$('popSpec').hidden` 이다. 카드가 열림 = `hidden=false` 를 지킨다. 현재 실태 탭에서는 **엔진 역사 실행의 마지막 관측 연도 상태**로 갱신 |
| `omega` | (새 카드) | 미래 예측: 기존 `setOmegaView(true)` + 설명 한 줄. 현재 실태: 작업대에 `omega`(모형) 카드를 넣는 버튼 |
| `sink` 탄소는 어디로? | `#popSink` | 그래프 옆 버튼은 그대로 두고, 카드로도 열 수 있게(같은 요소, 한 곳에만 보임) |
| `impacts` 영향 카드 | `#inqCards` (3D 위에 겹치던 것) | 3D를 가리지 않게 학습지로. `impactCards` 동작은 이 카드를 연다 |

## 3. E3 — 탐구 경로 재배치

경로 A(왜 CO₂가 증가했을까?)·B(해양 pH)는 지금 전부 `PAST_ONLY`(1750~2023, 예측 잠금)다 — 관측 자료만 보는 과제이므로 **현재 실태**로 옮긴다. 경로 C(기온, 시나리오 비교)는 **미래 예측**에 남긴다.

### A·B의 동작 바꾸기

| 지금 동작 (미래 예측 그래프용) | 현재 실태에서 |
|---|---|
| `showCharts: ['co2']` | `ws: { load: ['co2'] }` |
| `overlay: { chart: 'co2', series: 'fossil' }` | `ws: { load: ['co2', 'fossil'] }` |
| `timeRange` (PAST_ONLY) | 필요 없음 — 현재 실태는 전부 관측. 지운다 |
| `pickPoint: { chart: 'co2', saveAs }` | `pickPoint: { chart: 'ws', saveAs }` — 작업대 분석창 클릭 → Y1 계열의 가장 가까운 해 |
| `revealMarkers` | 작업대 분석창에 같은 표지(기존 `inquiryLayerPlugin` 을 작업대 차트에도 붙인다) |
| A5 `toggleNature` | `ws: { load: ['co2', 'co2_nature'] }` — "사람이 없었다면" 모형선(점선). 3D 자연 지구는 미래 예측 전용이라 쓰지 않는다 |
| B2 CO₂와 비교 | `ws: { load: ['co2', 'ph'] }` (뒤집기 버튼 사용 가능) |
| B3 `openPopover: spec` | `card: { id: 'spec' }` |
| B4 `omega` | `card: { id: 'omega' }` + 필요하면 `ws: { load: ['co2', 'omega'] }` |
| `focus3D` | 그대로(두 탭 3D 모두 같은 장면 구성) |

- 경로 C는 `tab: 'future'` 만 붙이고 동작은 그대로. C의 `impactCards` 는 학습지 카드로 뜬다.
- **질문·힌트·설명 문구는 바꾸지 않는다.** 단, 사라진 화면을 가리키는 문구("[자연만 있는 지구 보기]를 누르세요", "왼쪽 위 그래프")만 고치고 세이브포인트에 전·후 표.
- A6·B5(정리 단계)에 `askEvidence` 를 **하나씩 추가**한다(예: A6 `need: ['co2','fossil']`, B5 `need: ['co2','ph']`). 수업 담당자 확인이 필요하다고 세이브포인트에 적는다.
- `tools/test_inquiry.js`: 새 동작 형식 검사, `tab` 필드 필수, **탭에 맞지 않는 동작 금지**(current 경로에 `play`·`setScenario`·`toggleNature`, future 경로에 `ws`),
  `ws.load` 의 id가 `DATA_CATALOG` 에 있는지.

### 검사
- `node tools/test_inquiry.js` 통과(`--browser` 가능하면 함께).
- 🧑 현재 실태에서 경로 A를 처음부터 끝까지, B를 처음부터 끝까지. [이전]으로 돌아가도 같은 화면인가 / 증거 붙이기가 되는가 / 기록 CSV에 답이 다 있는가.
- 🧑 미래 예측에서 경로 C 전체.

## 4. E4 — 1인칭: 연도·시나리오 연동 + 야장 현장 과제

### 4-1. 같은 전 지구 값 쓰기 (10.27 피드백 2: 현재/미래/1인칭 데이터 통일)

- 지금 1인칭은 `#co2Slider`(280~1000 ppm)로 CO₂를 **직접** 넣는다 — 마스터 결정 9(CO₂는 결과)와 어긋난다.
- `firstperson/index.html` 에 `js/earth-data.js`, `js/earth-system.js` 를 추가(순서: `earth-model.js` → `earth-data.js` → `earth-system.js`, 빌더 `FP_JS` 도 같은 순서).
- 1인칭 조작을 **[시나리오] + [연도 1750~2200]** 으로 바꾼다. 고른 값으로 `EarthSystem.run` → 그 해의 전 지구 CO₂로 기존 `applyWorldCO2(ppm)` 를 부른다. ppm은 **읽기 전용 표시**.
  `#co2Slider` 는 지우지 않고 접힌 "교사용: 농도 직접 넣기" 안으로 옮긴다(기능 유지). `CO2_MIN/CO2_MAX` 불변.
- 1인칭 HUD의 값 표시에 **"전 지구 평균(조감 모드와 같은 모형)"** 과 **"이 지점"**(도시 열섬·나무 밑 CO₂ 같은 1인칭 고유의 공간 차이)을 구분해 적는다. 공간 차이 계산은 건드리지 않는다.
- 조감 → 1인칭 진입 링크에 상태를 넘긴다: `/firstperson/?scenario=ssp245&year=2100`(미래 예측) / `?year=<마지막 관측 연도>`(현재 실태). 1인칭은 주소의 값으로 시작.

### 4-2. 야장 현장 과제

- 1인칭에는 이미 야장(`fp-field.js`, F 키, 첫 탭 `tasks`)과 탐구 과제 목록이 있다. **그 목록 구조를 먼저 읽고 같은 구조로** 현장 과제 3개를 추가한다:
  ① 산호(해수온) ② 조개 껍데기(pH·Ω) ③ 빙하(기온) — 각각 "두 연도(예: 2023 / 고른 시나리오의 2100)에서 관찰하고 달라진 점 쓰기".
  과제 문구는 데이터로 두고(파일 위쪽 상수), 경로 C의 단계 id와 연결 키를 단다.
- 답은 `worksheet.v1.fp` 에 저장 → 조감 학습지 [기록] 탭에 "1인칭 현장 기록" 묶음으로 보인다. 야장의 기존 CSV 내보내기는 그대로.
- 야장을 열면 포인터 잠금이 풀리는지 확인(이미 그렇다면 그대로).

### 검사
- 공통 수용 조건 1·2·4. 1인칭 `CO2_MIN/CO2_MAX` 불변 확인.
- 🧑 미래 예측에서 현재 정책 2100 → [1인칭으로] → 같은 시나리오·연도로 시작하는가, HUD의 전 지구 CO₂가 조감 그래프의 값과 같은가.
- 🧑 야장 과제 답 쓰기 → 조감으로 돌아와 학습지 [기록]에 보이는가.
- 🧑 단일 HTML(file://)에서도 위가 되는가. **안 되면**(iframe 간 저장소가 갈리는 경우) 학습지에 "단일 파일에서는 1인칭 기록을 야장 CSV로 내보내 주세요" 안내를 띄우고, 세이브포인트에 실측 결과를 적는다.
