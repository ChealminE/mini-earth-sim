# 3차 F — 페트로바 스코프 (가시광 ↔ 적외선 보기)

> 마스터 규칙을 따른다. 기준 그림: `docs/refs/petrovascope.webp`(어두운 진홍 배경, 겹칠수록 밝아지는 보케 빛망울).
> **사람이 화면을 보며 맞추는 단계다.** 단계마다 🧑 확인을 받고 다음으로 간다. 스크린샷 반복 확인을 하지 않는다.
> 대상: 현재 실태·미래 예측의 종이 테마 씬. 직접 실험 탭 씬·1인칭은 범위 밖.

## 0. 과학적 기준 (바꾸지 말 것)

1. **CO₂는 가시광으로 보이지 않는다.** 가시광 보기에서는 지금처럼 대기가 투명하다(2차 D2 원칙 그대로 — 스모그·노란 안개 금지).
2. 적외선 보기는 **장파 복사(지구가 스스로 내보내는 열복사)** 를 보는 것이다. 지구가 적외선을 "반사"하는 것이 아니다.
   들어오는 햇빛은 주로 **단파(가시광)** 이므로 적외선 보기에서는 밝게 보이지 않는다.
3. **CO₂는 고르게 섞인 기체**다. 입자는 상자 공기 전체에 고르게 퍼뜨린다. 도시 굴뚝 근처에 모이게 하지 않는다.
4. 화면 문구의 파장: "장파 복사 관측 · CO₂ 흡수대 약 15 μm". **"8~15 μm" 를 쓰지 않는다**(8~13 μm는 CO₂가 거의 흡수하지 않는 '대기의 창').
5. 화살표·입자의 크기는 **엔진 값에서 계산**한다. 과장 표시는 배율을 화면에 적는다. 임의의 크기 공식(예: `1 + 1.5t`) 금지.
6. `earth-visual.js` 원칙 1 "변수 하나에 표현 하나": **입자 = CO₂의 양(ppm)**, **화살표 = 에너지 흐름(W/m²)**, **밝기 = 온도**. 서로 섞지 않는다.

## 1. 기술 기준 (이 저장소에서 확인된 것)

- 후처리(EffectComposer·UnrealBloomPass) **쓰지 않는다** — `vendor/three.min.js` 는 r160 레거시 UMD 빌드라 ES 모듈 애드온과 맞지 않고 단일 HTML 빌드가 깨진다.
  블룸 느낌은 **가운데가 밝은 보케 텍스처 + AdditiveBlending** 으로 낸다(겹치면 저절로 밝아짐).
- **transmission 재질 뒤의 반투명 물체는 사라진다**(2차 F5 구름 사건). 뚜껑(`lidMat`, common.js 770행 근처)만이 아니라 **옆벽 패널(`addPanel` 재질, 740행 근처, transmission 0.97)도** transmission이다.
  적외선 보기에서는 뚜껑을 `visible = false` 로 숨기고, 옆벽은 transmission 0 + 낮은 불투명도의 얇은 테두리선으로 바꾼다. 끌 때 둘 다 정확히 되돌린다(값 저장 후 복원).
  덤으로 '뚜껑이 열을 가둔다'는 온실 오개념도 피한다. 위·옆 두 카메라 각도 모두에서 입자가 보이는지 🧑 확인.
- 새 코드는 **`js/ir-scope.js`** 하나에 모은다: 순수 계산 `IRScopeCore`(node 검사용) + 씬 부품(만들기·갱신·켜고 끄기).
  index.html(`common.js` 뒤, `tab-current.js` 앞)과 빌더 `AERIAL_JS` 둘 다에 추가.
- 드로우콜 예산(마스터 §5-10): 꺼짐 +5 이하(만들어 두되 `visible=false`), 켜짐 +15 이하.
- `prefers-reduced-motion` 이면 입자 흐름·화살표 흐름을 멈춘 정지 화면.

## 2. F1 — 토글과 화면 톤

1. 3D 칸 오른쪽 위에 분할 토글 **[가시광 | 적외선]**(`btn--view`, `aria-pressed`, 키보드 조작). B3에서 숨긴 [CO₂ 보기] 자리를 대신한다(그 기능은 학습지로 이관, 지우지 않음).
2. 켜면:
   - `#gl` 캔버스에 CSS `filter` 로 **밝기 → 진홍 단색** 변환(예: `grayscale(1) sepia(1) saturate(5) hue-rotate(-40deg) brightness(0.7) contrast(1.2)` 에서 출발, 🧑로 맞춤).
     셰이더를 새로 쓰지 않고 장면 전체를 열화상처럼 만드는 가장 싼 방법이다. 필터 값은 CSS 토큰(`--ir-filter`)으로.
   - 3D 칸 위에 HTML 덮개 하나: 가장자리 비네팅(radial-gradient), 얇은 눈금 테두리, 왼쪽 아래 자막 "적외선(장파 복사) 보기 · CO₂ 흡수대 약 15 μm".
     덮개는 `pointer-events: none`. 덮개 글자도 13 px 이상·대비 기준 통과.
   - 장면 배경색을 어두운 진홍 토큰(`--ir-bg`)으로(`setSceneBackdrop`). 끌 때 원래 색.
3. 상태는 화면 공용(`IR.on`). 탭을 바꿔도 유지하고, 지금 탭의 씬에 적용한다.
4. 탐구 동작 `view3d` 에 `mode: 'ir'` 추가(E2 표에 한 줄). `tools/test_inquiry.js` 형식 검사에도.

🧑 **F1 확인**: 두 탭에서 켜고 끄기, 진홍 톤이 기준 그림과 비슷한가, 글자가 읽히는가, 끄면 완전히 원래대로인가. 필터 값은 사람이 고른 값으로 확정.

## 3. F2 — 밝기 = 온도

1. 적외선 보기에서 조명 램프(태양) 본체의 발광을 끄고 어두운 실루엣으로(기준 0-2: 단파 광원은 적외선 보기에서 밝지 않음).
2. 지표 세 구역(바다·숲·도시)의 밝기를 **전 지구 기온 편차 T**(그 해 엔진 값)에 따라 함께 올린다. 구역끼리의 차이(도시 > 바다 > 숲)는 **고정 오프셋**으로 두고
   ⓘ에 "구역 밝기 차이는 설명용 단순화(도시 열섬 등). 전체 밝기 변화만 모형 값" 이라고 밝힌다(등록부 새 키 `ir_zone_offset`, `unverified` 아님 — 근거는 설계 결정으로 적음).
   구현: 켤 때 각 재질의 `emissive`/`emissiveIntensity` 를 저장해 두고 바꾸며, 끌 때 정확히 되돌린다(마스터 §6-3: 재질 색은 텍스처에 곱해진다 — 밝히려면 emissive).
3. 구름은 적외선 보기에서 어둡게(구름 꼭대기는 차갑다). 불투명 재질 그대로 emissive만 낮춘다.

🧑 **F2 확인**: 1750 / 2023 / 2100(현재 정책) / 2200에서 전체 밝기가 오르는 게 보이는가, 구역 차이가 과하지 않은가.

## 4. F3 — CO₂ 입자 (페트로바 보케)

1. 보케 텍스처: 캔버스로 만든다(밝은 중심 → 부드러운 가장자리 → 아주 옅은 테두리 링). 이미지 파일을 추가하지 않는다.
2. `THREE.Points` **3겹**(작음·중간·큼, 크기와 불투명도가 다름), 각 겹 최대 개수를 미리 만들고 `setDrawRange` 로 보일 개수만 그린다(기존 `co2Dots` 와 같은 방식).
   재질: `AdditiveBlending`, `transparent`, `depthWrite: false`, 진홍~분홍 색(토큰).
3. **배치**: 기존 `co2Dots` 의 배치 코드(상자 공기 부피 안 균일 난수)를 함수로 뽑아 같이 쓴다. 천천히 떠다니되 한곳에 모이지 않게.
4. **개수 = ppm**: `EarthVisual.co2DotCount(ppm)` 와 같은 대응을 쓴다(가시광 쪽 [CO₂ 보기]와 같은 양이 같은 개수가 되게). 세 겹에 정해진 비율로 나눈다.
5. 뚜껑 숨김·옆벽 재질 바꾸기(§1). 위에서 내려다본 각도와 옆에서 본 각도 모두에서 입자가 보이는지 반드시 🧑 확인.

🧑 **F3 확인**: 1750(약 280 ppm)과 2200(현재 정책)의 밀도 차이가 분명한가, 기준 그림의 보케 느낌인가, 지형·도시가 입자에 너무 가려지지 않는가. 겹별 크기·불투명도는 사람이 고른 값으로 확정.

## 5. F4 — 에너지 화살표 5종

### 값 (`IRScopeCore.fluxes(ppm, T)` — 순수 함수, node 검사)

| 화살표 | 기준값 | 해마다 바뀌는 부분 | 근거 |
|---|---|---|---|
| ① 햇빛(단파) 들어옴 | 전 지구 평균 기준값 | 없음(엔진에 알베도 변화 없음) | 에너지 수지 그림 |
| ② 햇빛 반사(단파) | 기준값 | 없음 | 〃 |
| ③ 지표가 내보내는 장파 | 기준값 | `+ 4σT₀³ · T` (T₀ = 288 K, 약 5.4 W/m² per °C) | 슈테판-볼츠만 식의 선형화 |
| ④ 대기가 되돌려 보내는 장파 | 기준값 | `+ F` (F = `radiativeForcing(ppm, c0)`) | 엔진 강제력. **"단순화: 강제력만큼 늘어난 것으로 표시"** 를 ⓘ에 명시 |
| ⑤ 우주로 나가는 장파 | 기준값 | `− N` (N = F − λT, λ = `EarthSystem.PARAMS.lam`) | 엔진의 대기 꼭대기 불균형 |

- 기준값은 IPCC AR6 WG1 7장 지구 에너지 수지 그림에서 가져온다. **발췌본에 없으면** 등록부에 `unverified` 로 넣고 세이브포인트 "발췌 추가 필요: IPCC AR6 WG1 Ch.7 에너지 수지 그림 쪽"에 남긴다.
  사람이 쪽 이미지를 `docs/refs/발췌/` 에 올리면 대조해서 `verified` 로 바꾼다. 숫자를 기억으로 채워 `verified` 로 두지 마라.
- ⑤가 **불균형 동안만 줄고 기온이 따라 오르면 다시 회복**되는 것이 이 식으로 저절로 나온다 — '열이 영원히 갇힌다' 오개념을 막는 핵심이므로 단순화하지 마라.
- node 검사(`tools/test_earth_visual.js` 에 추가): 1750(ppm ≈ c0, T ≈ 0)에서 변화분 ≈ 0 / F > 0이면 ④ 증가 / 현재 정책 2200의 N이 2100의 N보다 작다(기온이 따라잡음) — 실제 출력값을 세이브포인트에.

### 그리기

- 화살표 굵기 = 기준 굵기 × (기준값 / 340). 기준 부분은 **실제 비율**, 변화분은 **다른 색 띠**로 덧붙이고 **고정 배율**(후보 ×10 / ×20, 🧑로 하나 확정)을 화살표 옆에 "변화량 ×10 확대" 처럼 적는다.
- 위치: ① 램프 → 지표, ② 지표 → 위쪽 바깥, ③ 세 구역에서 위로(작은 화살표 3개, 같은 값), ④ 대기층 높이에서 아래로, ⑤ 상자 위로 바깥.
  ①②는 적외선 보기에서 **외곽선만**(단파라서 이 보기에선 밝지 않음 — 기준 0-2).
- 재질: 흐르는 줄무늬 `ShaderMaterial` 하나를 모든 화살표가 공유(유니폼만 다름). 메시 최대 8개.
- 각 화살표 이름·현재 W/m² 값은 학습지 카드 `legend3d` 에 **적외선 절**을 추가해 보인다. 적외선 보기를 켜면 이 카드를 자동으로 연다(E2의 지시약 범례와 같은 방식). 3D 위에 범례를 겹치지 않는다.

🧑 **F4 확인**: 2023에서 ④의 변화 띠가 보이는가(배율 결정), 미래 예측 현재 정책을 2023 → 2200 재생할 때 ⑤의 부족분이 커졌다가 다시 줄어드는가, 화살표가 입자·지형을 너무 가리지 않는가.

## 6. F5 — 통합 · 성능

- 적외선 보기를 켠 채 탭 전환·재생·직접 설계·탐구 단계 이동이 모두 되는가. 탐구 단계의 기본 상태 되돌리기에 `IR.on` 포함(선언형).
- `tools/test_earth_visual.js` 에 생성 조건 검사(2차 F7처럼 소스 조건식): 꺼진 상태 `visible=false`, 뚜껑 숨김·복원 쌍, reduced-motion 분기.
- 🧑 **성능**: 이 노트북에서 개발자 도구 → Rendering → "Frame Rendering Stats"(FPS 표시)를 켜고, 미래 예측 1920×1080 적외선 보기 재생 중 FPS. 30 미만이면
  ① 입자 최대 개수 줄이기 ② 큰 겹 개수 줄이기 ③ CSS 필터를 끄고 장면 색만 바꾸기 순으로 제안하고 멈춘다.
- 스니펫으로 드로우콜(꺼짐/켜짐)을 받아 마스터 §5-10과 비교.
- 단일 HTML 빌드 후 file:// 에서도 적외선 보기가 되는가 🧑.
