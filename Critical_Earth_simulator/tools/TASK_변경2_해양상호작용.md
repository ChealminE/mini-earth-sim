# 작업 지시서 — 변경 2 (지점별 해수 상태 + 해양 흡수 흐름) + 변경 5

> 이 파일 하나로 작업을 끝낼 수 있게 썼다. 설계 원안은 저장소 루트 `10.09변경사항정리.md` 4절·7절.
> 선행 작업(변경 1)은 **이미 머지돼 있다** — `js/earth-model.js` 에 `seawaterState(ppm, tC, TA)` 가 있다.

## 작업 방식 — 반드시 지킬 것

**한 단계씩, 단계마다 커밋한다.** 아래 6단계를 순서대로 진행하고, 각 단계의 수용 조건을
통과한 뒤에 다음으로 넘어간다. 한 번에 다 고치고 마지막에 검증하지 말 것 — 틀어졌을 때
어디서 틀어졌는지 못 찾는다.

```
2-1 냉수대  →  2-4 해수 분석기  →  2-2 구역 CO₂ 상태화  →  2-3 해수 pCO₂  →  2-5 산호 연결  →  변경 5 야장
```

**범위 밖 (손대지 말 것):** 변경 3(CO₂ 동기화), 변경 4(실측 비교 카드), P0-2, P0-4.
조감 모드(`js/*.js`)는 2-6을 제외하면 건드리지 않는다. 2-6(미래 예측 기준 해역 UI)도 이번엔 제외한다.

## 막히면

어느 단계에서든 수용 조건을 못 맞추면 **그 단계까지만 커밋하고 멈춰라.**
억지로 수치를 맞추지 말고, 무엇이 왜 안 됐는지 PR 본문에 적어라.

## 2-1. 빙하 냉수대 (`firstperson/fp-world.js`)

현재 `seaTemperature(ppm)` 은 바다 전체가 하나의 값이다. 유빙 주변에 냉수대를 만든다.

```js
function seaTempAt(x, z, ppm) {
  const base = seaTemperature(ppm);   // 기존 함수 (CO2·계절 반영) — 그대로 둔다
  const p = iceProximity(x, z);       // 0 = 멀리, 1 = 유빙 바로 옆
  return base - COLD_POOL_DT * p;
}
```

- `COLD_POOL_DT` 초기값 **12** (모듈 상단 상수로 노출). `iceProximity` 는 `FPWorld.iceMeshes`
  각각의 월드 좌표까지 거리로 계산하고, 가장 가까운 유빙 기준으로 0~1 로 떨어뜨린다.
  감쇠 반경도 상수로 노출할 것.
- `seaTemperature(ppm)` 은 **지우지 말 것.** 기존 호출부가 쓰고 있고 `seaTempAt` 의 기준값이다.

**수용 조건**
- 유빙 바로 옆 해수온이 개방 해역보다 **10 °C 이상** 낮다.
- 맵 안 어디서도 해수온이 **−2 °C 밑으로 내려가지 않는다** (해수 어는점). 내려가면 하한을 걸 것.
- 유빙에서 충분히 먼 지점의 해수온이 기존 `seaTemperature(ppm)` 과 **0.1 °C 이내로 같다.**

## 2-4. 해수 분석기 (`firstperson/fp-tools.js`)

`HOTBAR_LABELS` **4번 슬롯이 비어 있다.** 거기에 넣는다.

```js
const HOTBAR_LABELS = ['온도계', 'pH미터', 'CO₂센서', '해수분석기', '', ...];
```

- 표시 항목: **용존 CO₂(µmol/kg), DIC(µmol/kg), Ω, 수온(°C)**.
  `seawaterState(pCO2, seaTempAt(x, z))` 에서 전부 나온다.
- 바닷물을 겨눴을 때만 동작한다. 육지·하늘이면 기존 pH미터처럼 `ERR`.
- 계측 오차 모형(`TOOL_SPEC`)을 따른다 — 분해능·반복도·응답지연. 즉시 확정되면 안 된다.
- 2번 pH미터도 **지점 해수 상태**를 읽도록 바꾸고, 표시창에 수온을 병기한다.
- 1번 온도계의 해수 측정도 `seaTempAt` 을 쓰게 한다.
- 조작법 패널(`H` 키)의 도구 설명도 갱신한다.

**수용 조건 (중요)**
- **온도계로 잰 해수온 == 해수 분석기가 보여주는 수온 == 산호가 반응하는 수온.**
  셋이 같은 함수를 쓰는지 코드로 확인할 것. 계측 노이즈 때문에 표시값은 다를 수 있으니,
  판정은 **모형 함수끼리** 비교한다.
- 418ppm·25 °C 에서 용존 CO₂ ≈ **11.9 µmol/kg**, DIC ≈ **2091 µmol/kg**.
  418ppm·2 °C 에서 ≈ **24.3** / **2225**. (설계안 3.3절 하단, 검증 완료된 값)

## 2-2. 구역 대기 CO₂를 상태 변수로 (`firstperson/fp-tools.js`)

기존 `CO2_ZONE` 고정 오프셋을 **국지 평형값(목표)** 으로 재해석하고, 실제 값이 그 목표를
향해 수렴하면서 바람을 타고 이웃 구역과 섞이게 한다.

```text
dC_z/dt = (C_bg + off_z(t) − C_z) / τ_z          ← 국지 평형 수렴 (기존 오프셋 재현)
        + w(t) · (C_upwind(z) − C_z) / τ_adv     ← 해륙풍 이류
```

- `w(t)`: 낮 = 해풍(바다 → 해변 → 녹지 → 도심), 밤 = 육풍(반대). 이미 있는 낮·밤 주기에 얹는다.
- 초기값 `τ_z` = 0.1일, `τ_adv` = 0.25일 (게임 시간, 하루 = 실시간 5분). 둘 다 상수로 노출.
- 상태 갱신은 **렌더 루프가 아니라 0.2초 틱**으로 돌린다.

**수용 조건 (설계안이 못박은 보정 기준)**
- **`w = 0`(바람 끔)으로 두고 정상 상태에 도달시켰을 때, 구역별 CO₂가 기존 `CO2_ZONE` 기반
  측정값과 ±2 ppm 이내여야 한다.** 낮·밤 둘 다 확인할 것. 이게 이 단계의 핵심 판정이다.
- 바람을 켜면 밤에 도심 CO₂가 해양 쪽으로 번져 해양 대기 CO₂가 올라가야 한다.

## 2-3. 해수 pCO₂의 동적 평형 (`firstperson/fp-world.js`)

```text
dpCO2_sw/dt = (C_ocean − pCO2_sw) / τ_sw
해수 상태   = seawaterState(pCO2_sw, seaTempAt(x, z))
```

- `τ_sw` = 2일(게임 시간). 상수로 노출.
- 해수는 대기 변화를 **천천히** 따라간다. "평형은 즉시가 아니라 시간에 걸쳐 도달한다"를 보이는 장치다.

**수용 조건**
- 대기 CO₂를 갑자기 올려도 해수 pH 가 **즉시 따라가지 않고** 시간에 걸쳐 수렴한다.
- 충분히 오래 두면 해수 pCO₂ 가 해양 대기 CO₂ 로 수렴한다 (±5 ppm).
- 밤 육풍으로 해양 대기가 30 ppm 오르면 해수 pH 가 **약 0.02** 내려간다.
  (418ppm 부근에서 1 ppm당 약 0.0007. pH미터 재현성 σ=0.02 와 비슷하므로 한 번 측정으로는
  안 보이는 게 정상이다 — 이건 버그가 아니라 설계 의도다. 야장 반복 측정으로 드러난다.)

## 2-5. 산호 반응 연결 (`firstperson/fp-world.js`)

- `calcificationHealth()` 가 **지점 Ω** 를 쓰게 한다 → 냉수대 산호부터 석회화가 약해진다.
- `coralBleaching()` 은 기존 로직을 유지하되 `seaTempAt` 을 쓴다.

**수용 조건**
- 같은 바다 안에서 **따뜻한 곳은 백화, 차가운 곳은 석회화 저해**라는 대비가 나타난다.
  (두 현상은 원인이 다르다 — 백화는 열 스트레스, 석회화 저해는 산성화. 이 구분이 기존 설계 의도다.)
- 1000ppm 에서 냉수대 Ω 가 1 미만이 되어 경고가 켜진다 (변경 1 검증값: 2 °C 에서 **0.6885**).

   (`earth-model.js` 를 공유하므로 자동이어야 하지만 깨지지 않았는지 확인.)
3. **단일 HTML 빌드** — `python Critical_Earth_simulator/tools/build_single_html.py` 성공.
   `firstperson/` 에 js 파일을 **새로 추가했다면** `tools/build_single_html.py` 의 `FP_JS` 목록과
   `firstperson/index.html` 의 `<script src>` 순서를 **둘 다** 맞춰야 한다.
   안 맞으면 빌드가 일부러 멈춘다.
4. **성능** — 상태 갱신이 렌더 루프가 아니라 0.2초 틱에서 도는지 확인.
   드로우콜이 기존 대비 크게 늘지 않았을 것 (지상 맑음 기준 약 481).

### 이 저장소에서 이미 데인 함정 (반복 금지)

- **`frustumCulled`** — three.js 는 `boundingSphere` 를 지오메트리 생성 때 한 번만 계산한다.
  정점을 매 프레임 갱신해도 다시 계산하지 않는다. 움직이는 파티클은 `frustumCulled = false`.
- **헤드리스 rAF 는 ~4 FPS** — 프레임 루프에 의존하는 검증은 거짓말이 된다. 고정 dt 로 직접 돌릴 것.
- **측정은 즉시 확정되지 않는다** — `FPTools.use()` 뒤에 `tool.reading` 이 null 이 될 때까지
  `FPTools.update()` 를 돌려야 `lastResult` 가 확정값이다.
- **한 프레임에 `render()` 를 두 번 부른다** (월드 + 도구 뷰모델). three.js 는 `render()` 마다
  `info.render` 를 리셋하므로, 루프 직후 드로우콜을 읽으면 뷰모델의 5개만 잡힌다.
- **계측 노이즈** — CO₂ σ=8 ppm, 온도계 σ=0.15 °C. 판정은 모형 함수로, 계측값은 느슨하게.
- **광선이 옆 생물에 맞는다** — 대상 외 생물은 `visible = false` 로 숨기고 잴 것.
- **카메라 조준** — 본 코드는 `camera.lookAt(eye + dir)` 규약이다.
  테스트에서 `camera.rotation.set(pitch, yaw, 0, 'YXZ')` 를 쓰면 x·z 가 뒤집힌다.
  순간이동 후에는 `camera.updateMatrixWorld(true)` 를 부를 것.
