## 작업 방식 — 반드시 지킬 것

**한 단계씩, 단계마다 커밋한다.** 각 단계의 수용 조건을 통과한 뒤 다음으로 넘어간다.
한꺼번에 고치고 마지막에 검증하지 마라 — 틀어졌을 때 어디서 틀어졌는지 못 찾는다.

커밋 메시지는 단계 번호와 내용을 적는다. 예: `3단계: 해수 분석기 (4번 슬롯)`.

### 막혔을 때

수용 조건을 못 맞추면 **억지로 수치를 맞추지 마라.** 대신:

- **다음 단계가 그 단계에 의존하지 않으면** → 못 한 이유를 기록하고 **다음으로 넘어가라.**
  (위 표의 "선행" 열을 보고 판단한다. 예: 4번이 막혀도 10번은 할 수 있다.)
- **다음 단계가 의존하면** → 거기서 **멈춰라.** 뒤를 억지로 하지 마라.

어느 쪽이든 **무엇이 왜 안 됐는지 PR 본문에 적는다.** 남은 건 다음에 사람이 이어서 한다.

## 전체 공통 수용 조건

작업이 끝나면(또는 멈추면) 아래를 확인한다.

1. `node --check` — 수정한 js 전부 통과.
2. **기존 수치가 안 바뀐다** — 25 °C 기준 pH 8.184 / 8.042 / 7.908 / 7.710,
   Ω 4.54 / 3.51 / 2.72 / 1.82 (280/418/600/1000 ppm). `earth-model.js` 를 안 건드렸으므로
   그대로여야 한다. **바뀌었으면 뭔가 잘못된 것이다.**
3. **두 모드 일치** — 조감·1인칭이 같은 CO₂·같은 수온에서 같은 pH·Ω.
4. **단일 HTML 빌드** — `python Critical_Earth_simulator/tools/build_single_html.py` 성공.
   js 파일을 **새로 추가했다면** `tools/build_single_html.py` 의 `AERIAL_JS` / `FP_JS` 목록과
   해당 `index.html` 의 `<script src>` 순서를 **둘 다** 맞춰야 한다. 안 맞으면 빌드가 일부러 멈춘다.
5. 콘솔 에러 0건.
6. **성능** — 상태 갱신은 렌더 루프가 아니라 0.2초 틱. 드로우콜이 크게 늘지 않을 것
   (지상 맑음 기준 약 481).

## 이 저장소에서 이미 데인 함정 (반복 금지)

1. **`frustumCulled`** — three.js 는 `boundingSphere` 를 지오메트리 생성 때 한 번만 계산한다.
   정점을 매 프레임 갱신해도 다시 계산하지 않는다. 움직이는 파티클은 `frustumCulled = false`.
2. **헤드리스 rAF 는 ~4 FPS** — 프레임 루프에 의존하는 검증은 전부 거짓말이 된다.
   물리·측정은 고정 dt 로 직접 돌려라 (`for (i=0;i<200;i++) FPTools.update(0.05)`).
3. **측정은 즉시 확정되지 않는다** — `FPTools.use()` 뒤에 `tool.reading` 이 null 이 될 때까지
   `FPTools.update()` 를 돌려야 `lastResult` 가 확정값이다.
4. **한 프레임에 `render()` 를 두 번 부른다** (월드 + 도구 뷰모델). three.js 는 `render()` 마다
   `info.render` 를 리셋하므로 루프 직후 드로우콜을 읽으면 **뷰모델의 5개만** 잡힌다.
   월드 비용은 직접 `render(FPWorld.scene, camera)` 한 뒤 읽어라.
5. **계측 노이즈** — CO₂ σ=8 ppm, 온도계 σ=0.15 °C. 한두 번 측정으로는 작은 차이를 분해할 수 없다.
   **판정은 모형 함수로, 계측값은 느슨한 범위로** 따로 확인하라.
6. **광선이 옆 생물에 맞는다** — 동물 41·어류 333마리다. 지형을 재는 테스트는 대상 외 생물을
   `visible = false` 로 숨기고 할 것.
7. **카메라 조준 규약** — 본 코드는 `camera.lookAt(eye + dir)` 다. 테스트에서
   `camera.rotation.set(pitch, yaw, 0, 'YXZ')` 를 쓰면 **x·z 가 뒤집힌다.**
   순간이동 후에는 `camera.updateMatrixWorld(true)` 를 부를 것.
8. **Chart.js 축을 하드코딩하지 마라** — 전에 `x: { max: 600 }` 을 박아놔서 슬라이더를 1000 까지
   올려도 곡선이 그래프 밖으로 나가는 버그가 있었다. `CO2_MIN`/`CO2_MAX` 를 쓸 것.
9. **재질 색은 텍스처에 곱해진다** — 흰색은 곱셈의 항등원이라 틴트로는 밝아지지 않는다.
   밝게 덮으려면 오버레이 메시를 쓸 것.
10. **테스트 설정 실수를 버그로 오인하지 마라** — 이상하면 테스트 쪽을 먼저 의심할 것.

## 브랜치와 마무리

- 기준 브랜치는 `feature/first-person-mode` (**`main` 아님**).
- **직접 푸시하지 마라** — 두 사람이 같이 쓰는 브랜치다.
  `feature/overnight-edu` 를 새로 따서 **단계마다 커밋**하고 **PR 하나**를 연다.
- 끝났으면(또는 멈췄으면) `Critical_Earth_simulator/yen진행상황.md` 의
  **10절·11절 체크박스**와 **작업 로그**를 갱신한다. 이번엔 한 세션뿐이므로 둘 다 손대도 된다.
- PR 본문에는 **"통과했다"가 아니라 각 단계 수용 조건의 실제 출력 숫자**를 적는다. 특히:
  - 1단계: 화학종 비율·절대 농도 표 (기준값과 대조)
  - 4단계: **바람 끈 상태(w=0)의 ±2 ppm 보정 결과** — 낮·밤 구역별 숫자 전부
  - 10단계: 레이아웃 **전후 스크린샷**
- **어디까지 했고 어디서 왜 멈췄는지**를 PR 맨 위에 한 문단으로 요약한다.
