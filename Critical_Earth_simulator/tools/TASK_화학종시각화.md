# 작업 지시서 — 화학종 분포 시각화 + 조감 모드 레이아웃

> 이 파일 하나로 작업을 끝낼 수 있게 썼다.
> **조감 모드 파일만 건드린다.** 1인칭(`firstperson/`)은 다른 세션이 동시에 작업 중이므로 **절대 손대지 말 것.**

## 왜 하나 — 이 작업의 요점

`js/earth-model.js` 의 `seawaterState()` 는 이미 **[CO₂(aq)] · [HCO₃⁻] · [CO₃²⁻] · DIC** 를 전부 계산한다.
그런데 **`earth-model.js` 밖에서 이 값을 쓰는 코드가 하나도 없다.** 학생이 보는 건 pH와 Ω라는 결과 숫자 둘뿐이다.

그래서 지금은 *"CO₂를 올리면 pH가 내려간다"* 가 **그렇다더라**로 끝난다.
**평형이 어느 쪽으로 이동했는지가 화면에 없다.** 르샤틀리에를 가르치려면 화학종이 움직이는 걸 봐야 한다.

계산은 이미 있으니 **표시 코드만** 붙이면 된다.

## 1. 화학종 분포 시각화

미래 예측 탭의 CO₂ 슬라이더에 연동되는 그래프를 하나 추가한다.
기존 산점도 2개(기온편차, pH) 옆이나 아래에 자연스럽게 배치한다.

**형식:** 가로 누적 막대 하나를 권장한다. DIC 를 100% 로 두고 세 화학종의 비율을 보여준다.
슬라이더를 끌면 막대 경계가 **실시간으로 움직여야** 한다. (Chart.js 가 이미 로드돼 있다.
직접 그리는 게 더 간단하면 canvas/div 로 해도 된다.)

함께 표시할 것:
- 세 화학종의 **절대 농도(µmol/kg)** 와 **DIC**. 비율만 보면 "총량도 느는데"를 놓친다.
- 막대 안이나 옆에 화학종 이름을 **화학식으로** 표기: `CO₂(aq)`, `HCO₃⁻`, `CO₃²⁻`.

**색:** 기존 팔레트와 맞춘다(`#85B7EB` 파랑, `#5DCAA5` 초록, `#E24B4A` 빨강, `#d08a2c` 주황 계열).
CO₃²⁻ 는 Ω 와 직결되므로 **Ω 수치 카드와 같은 색 계열**로 묶으면 연결이 보인다.

### 수용 조건 — 25 °C 기준, 이 값이 나와야 한다

| CO₂ | CO₂(aq) | HCO₃⁻ | CO₃²⁻ | DIC (µmol/kg) |
|---|---|---|---|---|
| 280 | 0.39 % | 85.47 % | 14.14 % | 2022 |
| 418 | 0.57 % | 88.85 % | 10.58 % | 2091 |
| 600 | 0.79 % | 91.23 % | 7.98 % | 2146 |
| 1000 | 1.28 % | 93.53 % | 5.19 % | 2214 |

절대 농도(µmol/kg), 280 → 1000 ppm:

- **CO₃²⁻ : 286 → 115** (약 60 % 감소)
- **HCO₃⁻ : 1728 → 2070** (증가)
- **DIC : 2022 → 2214** (증가)

표시값이 위와 **반올림 오차 범위 안에서** 일치해야 한다.

## 2. 완충 설명 — 이 작업의 교육적 핵심

위 숫자가 말하는 것은 하나의 반응이다:

```
CO₂ + CO₃²⁻ + H₂O  →  2 HCO₃⁻
```

바다에 들어온 CO₂ 가 **탄산이온을 잡아먹으면서 중탄산이온으로 바뀐다.**
그래서 (ㄱ) pH 가 생각보다 덜 떨어지고(= **완충**), (ㄴ) 그 대가로 **CO₃²⁻ 가 60 % 사라져**
아라고나이트 포화도 Ω 가 무너진다. **산호가 위험한 진짜 이유가 pH 자체가 아니라 이것이다.**

미래 예측 탭의 설명 문구(`<p class="hint">` 또는 `<p class="reg-note">` 근처)에 이 내용을
**두세 문장으로** 넣는다. 위 반응식을 포함할 것. 길게 쓰지 말 것 — 학생이 그래프를 보면서 읽을 문장이다.

**수용 조건:** 화면에 반응식이 있고, "완충"과 "CO₃²⁻ 감소 → Ω 하락"의 연결이 한 번에 읽힌다.

## 3. 조감 모드 와이드 화면 레이아웃

`style.css` 의 `grid-template-columns: 1fr 1fr 1fr` 때문에 3D 씬이 가로의 1/3 로 고정돼 있다.
1440×900 에서 캔버스가 **479×449** 로 잡히고 **화면 아래 1/3 이 빈 공백**이다.
교실 빔프로젝터가 대개 와이드라 체감이 크다.

- 넓은 화면에서 3D 씬과 오른쪽 패널의 비율을 조정하고, 세로 공백을 줄인다.
- 창 크기가 바뀌면 `fitRenderer()` 가 이미 호출된다. **3D 캔버스 크기 변경이 실제로 반영되는지 확인할 것.**
- 좁은 화면(노트북 1280 이하)에서 **기존보다 나빠지면 안 된다.** 둘 다 확인한다.

**수용 조건**
- 1440×900 에서 3D 캔버스 폭이 **기존 479px 보다 유의하게 커진다.**
- 1440×900 에서 세로 빈 공백이 눈에 띄게 줄어든다.
- 1280×800 에서 그래프가 잘리거나 겹치지 않는다.
- 스크린샷으로 전후를 비교해 PR 에 첨부한다.

## 전체 공통 수용 조건

1. `node --check` — 수정한 js 전부 통과.
2. **기존 수치가 안 바뀐다** — 280/418/600/1000 ppm 에서 기온편차·pH·Ω 표시값이 작업 전과 동일.
   (`earth-model.js` 를 안 건드렸으므로 당연히 그래야 한다. 바뀌었으면 뭔가 잘못된 것이다.)
   작업 전 값: pH 8.184 / 8.042 / 7.908 / 7.710, Ω 4.54 / 3.51 / 2.72 / 1.82.
3. **단일 HTML 빌드** — `python Critical_Earth_simulator/tools/build_single_html.py` 성공.
   `js/` 에 파일을 **새로 추가했다면** `tools/build_single_html.py` 의 `AERIAL_JS` 목록과
   `index.html` 의 `<script src>` 순서를 **둘 다** 맞춰야 한다. 안 맞으면 빌드가 일부러 멈춘다.
4. 콘솔 에러 0건.

### 이 저장소에서 이미 데인 함정

- **Chart.js 축을 하드코딩하지 말 것** — 전에 `x: { max: 600 }` 을 박아놔서 슬라이더를 1000 까지
  올려도 곡선이 그래프 밖으로 나가는 버그가 있었다. 범위는 `CO2_MIN`/`CO2_MAX` 를 쓴다.
- **재질 색은 텍스처에 곱해진다** — 흰색은 곱셈의 항등원이라 틴트로는 밝아지지 않는다. (3D 손댈 일 있으면)
- **헤드리스 rAF 는 ~4 FPS** — 프레임 루프에 의존하는 검증은 거짓말이 된다. 판정은 순수 계산으로.
- 검증에 Playwright 를 써도 되지만 **필수는 아니다.** 수치 판정은 node 로 `earth-model.js` 를
  직접 로드해서 할 수 있다.
